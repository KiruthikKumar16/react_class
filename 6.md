## SEGMENT 1: Validation 


**Add the validation starter dependency — check `pom.xml`:**

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-validation</artifactId>
</dependency>
```


**Annotate the entity:**

```java
package com.example.demo;

import jakarta.persistence.Entity;
import jakarta.persistence.GeneratedValue;
import jakarta.persistence.GenerationType;
import jakarta.persistence.Id;
import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.Size;

@Entity
public class Person {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @NotBlank(message = "Name is required")
    private String name;

    @Size(min = 2, max = 50, message = "Role must be between 2 and 50 characters")
    private String role;

    public Person() {}

    public Person(String name, String role) {
        this.name = name;
        this.role = role;
    }

    public Long getId() { return id; }
    public void setId(Long id) { this.id = id; }
    public String getName() { return name; }
    public void setName(String name) { this.name = name; }
    public String getRole() { return role; }
    public void setRole(String role) { this.role = role; }
}
```


> "`@NotBlank` rejects null, empty string, or whitespace-only. `@Size` bounds string length. Both take an optional `message` — that's what gets shown back to the client when validation fails, so make it something a frontend developer (or your future self) can actually understand."

**Activate it in the controller:**

```java
@PostMapping
public Person create(@Valid @RequestBody Person person) {
    return service.create(person);
}
```

**Say this — the key word here:**

> "That `@Valid` right before `@RequestBody` is the switch that turns validation on. Miss it, and every annotation you just wrote does nothing — Spring won't check them. This is genuinely the #1 mistake with Spring validation: writing the annotations, forgetting `@Valid`, then wondering why bad data still gets through."

**Test it — send a bad request in Postman:**

```json
{
  "name": "",
  "role": "A"
}
```

**Exercise (5 min):** add a `@NotBlank` to any field you haven't yet, test it fails correctly, then fix the request and confirm it succeeds.

## SEGMENT 2: Global Exception Handling



```java
package com.example.demo;

import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;

@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<String> handleValidation(MethodArgumentNotValidException ex) {
        String message = ex.getBindingResult().getFieldErrors().stream()
                .map(err -> err.getField() + ": " + err.getDefaultMessage())
                .reduce("", (a, b) -> a + b + "; ");
        return ResponseEntity.status(HttpStatus.BAD_REQUEST).body("Invalid input: " + message);
    }

    @ExceptionHandler(Exception.class)
    public ResponseEntity<String> handleGeneral(Exception ex) {
        return ResponseEntity.status(HttpStatus.INTERNAL_SERVER_ERROR)
                .body("Something went wrong: " + ex.getMessage());
    }
}
```


**Retest the same bad request from Segment 1:**

> "Send that same empty-name request again. Compare the response now to before — much cleaner, just `Invalid input: name: Name is required;`. That's what a real frontend can actually parse and show a user."

**Exercise (5 min):** deliberately trigger the general `Exception` handler — try GET on an id that doesn't exist, or force some other error, and confirm you get a clean 500 response instead of a raw stack trace.

## SEGMENT 3: CORS Configuration

**code:**

```java
package com.example.demo;

import org.springframework.context.annotation.Configuration;
import org.springframework.web.servlet.config.annotation.CorsRegistry;
import org.springframework.web.servlet.config.annotation.WebMvcConfigurer;

@Configuration
public class CorsConfig implements WebMvcConfigurer {

    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/api/**")
                .allowedOrigins("http://localhost:5173")
                .allowedMethods("GET", "POST", "PUT", "DELETE");
    }
}
```

**common deployment errors:**

| Error | Cause | Fix |
|---|---|---|
| Build fails on Render | Wrong Java version, or `mvnw` not executable | Check `pom.xml` Java version matches Render's runtime; ensure `mvnw` has execute permissions (`chmod +x mvnw` before pushing) |
| App crashes immediately on Render, works locally | Environment variables not set on Render dashboard | Double-check `DB_URL`/`DB_USERNAME`/`DB_PASSWORD` are added under Render's Environment tab |
| CORS error only on deployed frontend, works locally | Deployed frontend URL missing from `allowedOrigins` | Add the exact deployed URL, https, no trailing slash, redeploy backend |
| 502/503 on first request | Render free tier spins down idle services; first request wakes it up, can take 30+ seconds | Expected behavior on free tier — not a bug, just wait |
| Connection refused to Supabase from Render | Supabase project paused, or IP restrictions on the Supabase side | Check Supabase project is active; check any network restrictions in Supabase settings |
